# Sustainable Finance MEL Platform Known Issues

- Product identity has been revised from TACATDP to Sustainable Finance MEL Platform. Do not blindly rename existing `TACATDP_*` Power Platform artifacts because deployed schemas, lists, controls, and source-form terminology may still depend on those names. Use Sustainable Finance MEL Platform for documentation/product identity and TACATDP for historical/programme/deployed artifact context.

- On 2026-08-24, CRDB XML upload through the browser baseline-import page failed with `403` / `90040103` / `EntityPermissionCreateIsMissing` for `mp_formversion`. This is a Power Pages table-permission blocker, not proof that PAC auth or the XML file is invalid. The effective portal administrator role needs `Create` on `mp_formversion`; relationship binds may then require `Append` on `mp_formversion` and `Append To` on `mp_form`. Pause further CRDB retries until CRDB personnel can update/check table permissions.
- On 2026-08-24, new CRDB information indicated a possible Docker-capable environment. Record this as a stoppage/pivot point: Power Pages may still need demonstration maintenance, but the scalable SFU MEL product may move to a new Django/PostgreSQL/Redis/Celery/Viewflow repository after research and planning.

- Configuration Migration Tool schemas use lowercase Dataverse logical names and encode lookup fields as `type="entityreference"` with `lookupType` set to the referenced table logical name. Using the generic `type="lookup"` causes target validation to report valid lookup columns as missing. CMT 9.1.0.365 still rejected the valid `mp_formattachment.mp_file` column when encoded as `filedata`; use the governed Package Deployer release with Dataverse block file messages for the TACATDP seed and XForm instead of patching CMT archives.
- CRDB Power Pages onboarding can create Contact, Invitation, and `mp_formassignment` rows without completing Microsoft identity activation. On 2026-07-31, CRDB checks showed Denis and Hailo had `adx_externalidentity` rows and could access the portal, while affected non-admin invitees had active assignments and active `New` invitations but no external identity rows; `adx_inviteredemption` returned no records. Treat users as `Pending activation` until the invitation is redeemed, the invitation leaves `New`, and an `adx_externalidentity` exists. Do not diagnose this as an app assignment/email-pattern issue until contact uniqueness, invitation status, invite redemption, external identity, web role, and assignment are checked together.
- Private Power Pages site visibility is a separate access gate before TACATDP web roles, table permissions, invitations, and assignments. In Mshirika and CRDB developer/non-production sites, non-admin testers must be added under Power Pages Studio > Security > Site visibility > Grant site access before invitation redemption/sign-in can complete. If the public/private radio controls are disabled, do not diagnose TACATDP code first: Microsoft tenant governance or developer-site restrictions may be forcing the site to remain private. The correct private-site test checklist is: grant site access for the CRDB Entra user, then redeem invitation, then verify `adx_externalidentity`, web role, and active assignment.
- The Power Pages ODK runtime must not rely only on the third-party `loaded` event to remove a blocking form loader. On 2026-07-31, CRDB showed the runner stuck at "Preparing the form runtime" while the form appeared blurred behind the overlay. Keep a timed mount fallback that clears the overlay after the ODK host mounts, and show an actionable status instead of trapping the user behind a full-screen spinner.
- Power Pages site exports can include secret-bearing `sitesetting.yml` values. On 2026-08-02, GitHub push protection blocked TACATDP branch push because the CRDB deployment artifact included an Azure AD application secret in `artifacts/deployments/.../tacatdp-monitoring-tool/sitesetting.yml`. Do not commit raw Power Pages `sitesetting.yml` exports from live environments. Scrub or omit sensitive site settings before packaging documentation artifacts, and verify with secret scanning before push.
- Power Pages SPA asset renames can leave users on stale shell code even after portal cache purge and site restart. On 2026-08-03, Mshirika still showed the old shell because localized Home content and old JS/CSS web-file names were not updated together. For shell releases, verify both the main Home page and localized Home copy reference the current asset marker, and overwrite previous JS/CSS asset filenames as compatibility aliases until old cached HTML can no longer be served. Confirm by downloading the live site with PAC and scanning the returned Home pages plus old asset filenames for stale route markers and forbidden shell controls.

Do not route CRDB one-row fixes through Azure CLI when Denis lacks Azure tenant permission. For record writes use one of: approved service principal/Azure token, model-driven/Maker table UI, Power Pages Web API from an authorised admin session, or a packaged server-side processor.
- Project/form visibility requires both the correct Power Pages web role and an active TACATDP assignment row. On 2026-08-04, CRDB showed Denis and Hailo both linked to the same `Platform Administrator` web role, but Hailo's `mp_formassignment` row did not return `mp_lifecyclestatus=Active`; the SPA filters assigned forms by `mp_lifecyclestatus eq 100000000`, so Hailo can have the right portal role and still see zero projects. - Power Pages Web API routes must use the Dataverse `EntitySetName`, not a guessed plural. On 2026-08-15, Mshirika direct PAC metadata showed `mp_TrackedEntity` existed with `entitysetname=mp_trackedentitys`. The browser baseline-import diagnostics failed for every `/_api/mp_trackedentities` read/create with generic `400` / `9004010A`, even though direct PAC Dataverse read worked and Power Pages table permission/site settings existed for logical table `mp_trackedentity`. The fix was to use `/_api/mp_trackedentitys` and bind child lookups to `/mp_trackedentitys(<id>)`; `scripts/validate-baseline-tracked-entity-entityset.mjs` prevents regression.
- Power Pages browser lookup binds can remain blocked even after table-permission UI appears correct. On 2026-08-15, Mshirika `mp_project` and `mp_trackedentity` permissions had the expected `Read/Create/Append/Append To` privileges and Portal Management showed `Administrators`/`Authenticated Users` rows, but `POST /_api/mp_trackedentitys` with `mp_Project@odata.bind` still returned `90040106 EntityPermissionAppendToIsMissingDuringAssociationChange`. Microsoft docs confirm `@odata.bind` is an association and requires `Append` on the source plus `Append To` on the referenced table; Power Pages config/data cache can also lag up to 15 minutes. For the prototype browser importer, stop cycling on permission edits after one verified privilege/cache pass: create `mp_trackedentity` and `mp_beneficiaryprofile` without the non-essential `mp_Project@odata.bind`, preserve project identity through import context/lineage, and revisit project lookup association through an approved server-side Dataverse Web API/import path.
- Power Pages Web API field allow-lists must include every property selected or filtered by browser upsert checks, including lookup shadow properties. On 2026-08-15, after the tracked-entity create path was unblocked, Mshirika baseline import failed at `mp_EntityIdentifier` with `90040101 AttributePermissionIsMissing` first for selected primary id `mp_entityidentifierid`, then for filtered lookup property `_mp_trackedentity_value`. Microsoft Power Pages read-operation docs show lookup reads using `_primarycontactid_value`; the same exact shadow-property name must be enabled in `Webapi/<table>/fields` if `$select` or `$filter` uses it. The fix added `mp_entityidentifierid`, `mp_beneficiaryprofileid`, `mp_beneficiarysubmissionlinkid`, and `_mp_trackedentity_value` where used, and extended `scripts/validate-baseline-tracked-entity-entityset.mjs`.
- Power Pages Web API field allow-lists must also include exact case-sensitive navigation property names used by browser `@odata.bind` payloads. On 2026-08-15, after primary id and shadow lookup fields were enabled, Mshirika baseline import failed again at `mp_EntityIdentifier` with `90040101 AttributePermissionIsMissing` for `mp_TrackedEntity` because the payload used `mp_TrackedEntity@odata.bind` while `Webapi/mp_entityidentifier/fields` only listed `mp_trackedentity` and `_mp_trackedentity_value`. The fix is to enable `mp_TrackedEntity` on entity identifier and beneficiary profile fields, and `mp_TrackedEntity` plus `mp_Submission` on beneficiary submission link fields, then validate against the exact browser payload properties.
- Creating `mp_trackedentity` rows through Power Pages requires `Append To` on `mp_project` for the effective web role used by the import session, not only read access to projects. On 2026-08-15, Mshirika diagnostics passed `/_api/mp_projects` lookup and all `/_api/mp_trackedentitys` reads, but `POST /_api/mp_trackedentitys` with `mp_Project@odata.bind` failed with `90040106 EntityPermissionAppendToIsMissingDuringAssociationChange`. Studio showed `mp_project` read permission for `Authenticated Users`, but the import session also needed the `Administrators` role associated to the same read/append-to permission. Keep `mp_project` create/write/delete disabled; grant read plus append-to and link both `Authenticated Users` and `Administrators` for admin imports.
