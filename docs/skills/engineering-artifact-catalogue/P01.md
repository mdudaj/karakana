## Outcome, scope and artifact readiness

Give subsequent skill/tool implementation one generic, Markdown-first contract
for content, stable identity, source authority, audience exports and feedback.
Users author documentation in Markdown and share derived Excel views. Existing
engine-owned structured data retains its source authority. Global blank assets
contain no project names, domain capabilities, assigned people or release facts.

Reuse [research](RESEARCH.md), [detailed proposal](PLAN.md), the accepted
[blank template](TEMPLATE.md), and the [engineering lifecycle](../../engineering-process.md).
Required artifacts: this scope/requirements/traceability/safety/recovery record;
the [ADR](../../adr/0005-markdown-engineering-artifact-contract.md);
the [content contract](../../engineering-artifacts.md); complete synthetic examples;
the accompanying generic blank workbook; verification and append-only handoff.
Product UX screens, migrations and production rollout are not applicable: this
slice changes documentation and package assets, not runtime application behavior.

Non-goals: implement exporter/adapter code, change engine schemas/readiness,
install/promote skills, modify protocols/model routes, draft a real project's
release, claim independent review, push, publish, merge or deploy.

## Inspected engine and harness evidence

Baseline inspected: task branch at `cd3deee` (2026-09-26).

| File / interface | Observation | Contract implication |
| --- | --- | --- |
| `karakana/requirements/schemas.py::RequirementPRD` | `req_id` identifies a PRD; functional/nonfunctional requirements and criteria are string lists; `project` is optional | Do not treat the aggregate PRD ID as an individual requirement ID; use a binding registry and require namespace confirmation |
| `schemas.py::UserStory` | `story_id` and `req_id` exist; criteria have no IDs; there is no metadata field | Do not inject new top-level fields or assume every schema has extensible metadata |
| `schemas.py::IssueDraft` | `issue_id`, `req_id`, optional `story_id`, string criteria and metadata exist | Preserve source lineage; copied criteria do not prove shared identity |
| `schemas.py::from_dict` | Dataclass constructors consume known keys | New mandatory/unknown fields can break consumers; registry is separate |
| `karakana/requirements/store.py` | Loads JSON; saving rewrites JSON and rendered Markdown; source/revision version field absent | Engine JSON stays authoritative; hash exact source files; do not edit generated Markdown as a master |
| `karakana/requirements/summary.py` | PRD/story Markdown omits some native IDs/status and uses title headings | Import identities from JSON, not rendered headings; readable summary is not a lossless identity registry |
| `karakana/requirements/stories.py`; `issues.py` | Generated story/issue IDs use the current enumeration; criteria are copied strings | Read existing records without invoking generators; regeneration needs explicit reconciliation, not an export side effect |
| `karakana/requirements/readiness.py` | Checks presence/shape and has project-specific rules; ready is not approval | Preserve result vocabulary and evidence limits; do not replace it with workbook readiness |
| `karakana/protocols/checks.py` | Readable nonempty artifact files pass presence checks | Attach substantive canonical content and review evidence; no semantic assurance from repeated path attachment |
