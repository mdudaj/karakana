# Bounded milestones

A useful milestone has a goal, observable output, checkpoint and acceptance, linked
to an outcome/source baseline. Prefer small demonstrable slices that produce feedback;
do not equate code-layer completion or document count with value.

Record owner, dependencies and estimate basis. Unknown owner/effort/dates remain
unconfirmed. Distinguish a proposed milestone, forecast target, agreement and actual
completion. Agreement needs the existing authority/evidence for that source revision.

Set acceptance at the output level: what can be inspected or used, which meaningful
checks must pass, which gaps prevent reliance and who must review. A drafted milestone
cannot substitute for observed completion, user acceptance or a release decision.

Order dependencies and checkpoints so the next bounded task is actionable. Identify
blocking decisions or evidence needs explicitly. Reuse an approved plan; reopen only
changed assumptions. Tailor tiny fixes to a compact record rather than every table.

Link milestone/output to relevant requirements, decision records and test/evidence
plans. Preserve changed baseline/history and explain forecast revisions. Use
Milestones plus typed Links when exporting. Basis:
[research/plan](../../../docs/skills/engineering-artifact-catalogue/PLAN.md), S10/S23 and
existing delivery-artifact-gate/engineering lifecycle.
